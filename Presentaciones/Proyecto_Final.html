¿Qué características de los árboles se relacionan con daño observado en las veredas?

Un análisis educativo del censo de arbolado de NYC para entender datos, modelos y sus límites.

Enzo Fernández · Juan Ignacio Olivares · Gabriel Quispe

Notas para exponer

Presentar la pregunta y anticipar el límite clave: el trabajo clasifica lo registrado en 2015, no predice futuras roturas.

1:00

01 · Motivación

¿Por qué estudiar este problema?

Impacto cotidiano

Las veredas dañadas pueden dificultar la circulación y requieren mantenimiento.

Pregunta de datos

¿Hay patrones entre el arbolado, su entorno y el estado de vereda registrado junto a cada árbol?

Valor del proyecto

Aplicar un flujo completo de ciencia de datos y practicar una evaluación responsable.

Objetivo real: clasificar `Damage` / `NoDamage` según la observación del censo. No estimamos cuándo se dañará una vereda.
Notas para exponer

Explicar la motivación como un caso para aprender y generar hipótesis. No decir que el modelo ya prioriza obras ni que reduce accidentes.

Cada barra usa la etiqueta observada en la muestra de 100.000 árboles; la última categoría tiene 984 casos.

¿Qué hicimos con los datos?

  • Revisamos faltantes, tipos, rangos y balance de clases.
  • Resumimos 9 indicadores de conflictos en 3 puntajes.
  • Usamos `sidewalk` como etiqueta, nunca como predictor.
Interpretación: los árboles grandes presentan más daño registrado en esta muestra. Esto no demuestra que el diámetro sea la causa.
Notas para exponer

Leer la tendencia de izquierda a derecha y enfatizar que son porcentajes descriptivos. Pueden influir especie, ubicación, mantenimiento, calidad del registro y otras variables.

Ojo con accuracy: el modelo tuvo 0,708; Dummy tuvo 0,712, pero Dummy obtuvo F1=0 y recall=0 en `Damage`.

Matriz de confusión · filas reales, columnas predichas

Pred. NoDamagePred. Damage
Real NoDamage10.6233.622
Real Damage2.2163.539

10.623 y 3.539 aciertos · 3.622 falsas alarmas · 2.216 daños observados no detectados.

Lectura simple: recupera 61,5% de los daños registrados; de todas formas, no detecta 38,5%.
Notas para exponer

F1 equilibra precisión y recall para la clase Damage. Precision 0,494 implica que cerca de la mitad de las alertas son falsas; recall 0,615 implica que queda daño observado sin detectar. No afirmar que el modelo es “preciso” en términos generales.

¿Qué separa a los grupos?

  • Mediana de diámetro: 11, 8 y 16 pulgadas.
  • Mediana de conflictos de raíz: 0, 0 y 1.
  • DBSCAN: 5 grupos y 1,2% de puntos marcados como ruido.
Silhouette bajo/modesto y codificación categórica: interpretación cautelosa. No son grupos “de riesgo”.
Notas para exponer

Se excluyeron sidewalk y target. K-Means y DBSCAN se aplicaron a características del árbol y entorno. Los resultados dependen de muestra, variables, escalado y parámetros; no validan perfiles reales.

07 · Del análisis a una demo

Una API para demostrar el flujo de inferencia

Cómo levantarla

python Final/train.py
uvicorn Final.app:app --reload

Luego abrir /docs y probar `POST /predict`.

También hay un endpoint `GET /health`.

Qué entra y qué sale

Entrada: diámetro, especie, salud, borough y conflictos observados.

Salida: clase estimada y probabilidad del modelo.

Probabilidad ilustrativa, no calibrada para decisiones operativas. La API no está desplegada públicamente.
Notas para exponer

Mostrar Swagger `/docs` si hay tiempo; si no, explicar que FastAPI valida el JSON y pasa las variables al mismo pipeline usado en entrenamiento. No presentar la API como sistema de producción.

08 · Cierre

La principal conclusión es también un límite

Lo que aprendimos

Un flujo reproducible convierte registros públicos en análisis, evaluación y una demo de API.

Lo que falta para uso real

Datos recientes y locales, validación por zona, revisión humana, auditoría de sesgos y consulta comunitaria.

Mensaje final: clasificamos una observación histórica de NYC (2015); no predecimos daño futuro ni recomendamos intervenciones automáticas.
